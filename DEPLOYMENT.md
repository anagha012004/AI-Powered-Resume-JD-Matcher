## 1. Local Development

### Prerequisites

| Tool | Version | Install |
|------|---------|---------|
| Python | 3.12.x | [python.org](https://python.org) |
| uv | latest | `pip install uv` |
| Node.js | 18+ | [nodejs.org](https://nodejs.org) |
| Redis | any | Docker: `docker run -d -p 6379:6379 redis:alpine` |

### Backend

```bash
cd apps/backend
cp .env.example .env
# Edit .env — fill in at minimum GEMINI_API_KEY and SECRET_KEY
uv sync --dev --no-install-project
uv run uvicorn app.main:app --reload --port 8000
```

- API: http://localhost:8000
- Swagger UI: http://localhost:8000/docs
- ReDoc: http://localhost:8000/redoc

### Frontend

```bash
cd apps/frontend
cp .env.local.example .env.local
# .env.local already has: NEXT_PUBLIC_API_URL=http://localhost:8000
npm install
npm run dev
```

- App: http://localhost:3000

## 3. Docker (self-hosted)

### Build and run the backend

```bash
cd apps/backend
docker build -t resume-matcher-api .
docker run -d \
  --name resume-api \
  -p 8000:8000 \
  -e GEMINI_API_KEY=your_key \
  -e SECRET_KEY=your_32_char_secret \
  -e REDIS_URL=redis://host.docker.internal:6379 \
  -e DATABASE_URL=sqlite+aiosqlite:///./resume_matcher.db \
  resume-matcher-api
```

### Docker Compose (full stack)

```yaml
# docker-compose.yml (place at project root)
version: "3.9"
services:
  redis:
    image: redis:alpine
    ports: ["6379:6379"]

  api:
    build: ./apps/backend
    ports: ["8000:8000"]
    environment:
      GEMINI_API_KEY: ${GEMINI_API_KEY}
      SECRET_KEY: ${SECRET_KEY}
      REDIS_URL: redis://redis:6379
      DATABASE_URL: sqlite+aiosqlite:///./resume_matcher.db
    depends_on: [redis]
    volumes:
      - ./apps/backend:/app   # hot-reload in dev

  frontend:
    image: node:18-alpine
    working_dir: /app
    volumes: ["./apps/frontend:/app"]
    ports: ["3000:3000"]
    environment:
      NEXT_PUBLIC_API_URL: http://localhost:8000
    command: sh -c "npm install && npm run dev"
    depends_on: [api]
```

```bash
GEMINI_API_KEY=xxx SECRET_KEY=yyy docker compose up
```

## 4. Production: Render + Vercel (recommended)

This is the zero-infrastructure path. Total cost: **$0** using free tiers.

### Step 1 — Push to GitHub

```bash
git init
git add .
git commit -m "initial commit"
git remote add origin https://github.com/YOUR_USERNAME/resume-matcher.git
git push -u origin main
```

### Step 2 — Deploy Backend to Render

#### Option A — Blueprint (one-click)

1. Go to [render.com/deploy](https://render.com) → **New** → **Blueprint**
2. Connect your GitHub repo
3. Render detects `render.yaml` at the project root and creates:
   - `resume-matcher-api` (web service)
   - `resume-matcher-redis` (Redis instance)
4. In the dashboard, set the secret environment variables:

```
GEMINI_API_KEY     → your Gemini key
GROQ_API_KEY       → your Groq key (optional)
OPENROUTER_API_KEY → your OpenRouter key (optional)
```

`SECRET_KEY` is auto-generated by the blueprint.

#### Option B — Manual

1. **New Web Service** → connect repo → set root dir: `apps/backend`
2. Runtime: **Python 3**
3. Build command:
   ```
   pip install uv && uv sync --no-dev --system
   ```
4. Start command:
   ```
   uvicorn app.main:app --host 0.0.0.0 --port $PORT
   ```
5. Add a **Redis** add-on, copy the `REDIS_URL` into env vars
6. Set all env vars from the table in Section 5

After deploy, note your backend URL e.g. `https://resume-matcher-api.onrender.com`

### Step 3 — Deploy Frontend to Vercel

```bash
cd apps/frontend
npx vercel
```

When prompted:
- Link to existing project? **No**, create new
- Directory: `./` (you're already in `apps/frontend`)
- Framework: **Next.js** (auto-detected)

Then set the environment variable in the Vercel dashboard:

```
NEXT_PUBLIC_API_URL = https://resume-matcher-api.onrender.com
```

Or via CLI:

```bash
vercel env add NEXT_PUBLIC_API_URL production
# paste: https://resume-matcher-api.onrender.com
vercel --prod
```

### Step 4 — Update CORS

Add your Vercel URL to the backend CORS list in `apps/backend/app/main.py`:

```python
allow_origins=[
    "http://localhost:3000",
    "https://*.vercel.app",
    "https://your-app.vercel.app",  # add your exact domain
],
```

Re-deploy the backend after this change.

### Final URLs

| Service | URL |
|---------|-----|
| Frontend | `https://your-app.vercel.app` |
| Backend API | `https://resume-matcher-api.onrender.com` |
| Swagger UI | `https://resume-matcher-api.onrender.com/docs` |
| Health check | `https://resume-matcher-api.onrender.com/health` |

## 5. Environment Variables Reference

### Backend (`apps/backend/.env`)

| Variable | Required | Description |
|----------|----------|-------------|
| `SECRET_KEY` | **Yes** | JWT signing key — min 32 chars. Generate: `python -c "import secrets; print(secrets.token_hex(32))"` |
| `GEMINI_API_KEY` | **Yes** | Primary LLM. Free at [aistudio.google.com](https://aistudio.google.com/app/apikey) |
| `GROQ_API_KEY` | No | First fallback LLM. Free at [console.groq.com](https://console.groq.com) |
| `OPENROUTER_API_KEY` | No | Second fallback. Free at [openrouter.ai](https://openrouter.ai) |
| `REDIS_URL` | **Yes** | `redis://localhost:6379` locally, or from Render/Upstash |
| `DATABASE_URL` | **Yes** | `sqlite+aiosqlite:///./resume_matcher.db` (dev) or Neon PostgreSQL URL (prod) |
| `GEMINI_MODEL` | No | Default: `gemini-2.0-flash` |
| `GROQ_MODEL` | No | Default: `llama-3.3-70b-versatile` |
| `OPENROUTER_MODEL` | No | Default: `meta-llama/llama-3.3-70b-instruct:free` |
| `LOW_SIMILARITY_THRESHOLD` | No | Default: `0.25` — cosine score below which LLM is skipped |
| `CACHE_TTL` | No | Default: `86400` (24 hours in seconds) |

### Frontend (`apps/frontend/.env.local`)

| Variable | Required | Description |
|----------|----------|-------------|
| `NEXT_PUBLIC_API_URL` | **Yes** | Backend base URL e.g. `http://localhost:8000` |

## 6. Getting Free API Keys

### Gemini 2.0 Flash (primary — required)
1. Go to [aistudio.google.com/app/apikey](https://aistudio.google.com/app/apikey)
2. Click **Create API key**
3. Free tier: 1M tokens/min, 1500 requests/day

### Groq (first fallback — recommended)
1. Go to [console.groq.com](https://console.groq.com)
2. Sign up → API Keys → **Create API Key**
3. Free tier: 14,400 requests/day on `llama-3.3-70b-versatile`

### OpenRouter (second fallback — recommended)
1. Go to [openrouter.ai](https://openrouter.ai) → Sign in
2. Settings → API Keys → **Create Key**
3. Free tier: `meta-llama/llama-3.3-70b-instruct:free` — rate-limited but free

Having all three configured means the app stays up even when any one provider hits rate limits.

## 7. PostgreSQL Migration

This project uses [Neon](https://neon.tech) as the managed PostgreSQL provider.

### Getting a free Neon database

1. Go to [neon.tech](https://neon.tech) → **Sign up** (free tier: 0.5 GB storage, 1 compute)
2. Create a new project → select a region closest to your Render service (e.g. `us-west-2` for Oregon)
3. In the **Connection Details** panel, select **Connection string** and copy the URL
4. It looks like:
   ```
   postgresql://user:password@ep-xxx.us-west-2.aws.neon.tech/neondb?sslmode=require
   ```

### Setting the env var

Paste the Neon URL as `DATABASE_URL` in your Render service's environment variables. The `database.py` module automatically rewrites it to `postgresql+asyncpg://...` and enables SSL.

No code changes needed — SQLAlchemy handles the rest. The schema is created automatically on startup via `create_all`.

## 8. Troubleshooting

### Backend won't start — "No module named 'app'"
```bash
cd apps/backend   # must run from this directory
uv run uvicorn app.main:app --reload
```

### Redis connection refused
```bash
docker run -d -p 6379:6379 redis:alpine
```
Redis failures are silent — the app degrades gracefully (slower, no caching).

### "All LLM providers failed" in production
- Check all three API keys are set in the dashboard
- The app shows a countdown timer and retries automatically after the rate-limit window

### MiniLM model slow on first request
The Docker image pre-downloads the model during build. For uv installs, the model downloads on first request (~300ms, cached after).

### CORS errors in browser
Add your frontend URL to `allow_origins` in `apps/backend/app/main.py` and redeploy.

### PDF export fails
```bash
uv add reportlab
# or pip install reportlab
```

### Tests fail with "no such table"
The test database is created fresh each session. If it exists from a previous aborted run:
```bash
cd apps/backend
rm -f test_resume_matcher.db
uv run pytest -v
```
